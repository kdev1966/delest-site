Le cœur

L’Arbitre, le cœur de Delest

Un nettoyeur classique supprime ce qui ressemble à un cache. Delest fait l’inverse : il ne propose que ce qu’il peut prouver reconstructible, et il vous montre sa preuve.

Seulement ce qui se reconstruit

target, node_modules, build, .gradle, .venv, Pods, .next : reconnus à leur manifeste et à leur lockfile, jamais à leur seul nom.

Chaque verdict expliqué

Ignoré par git, à côté de son manifeste, dernier commit il y a trois jours : chaque proposition vient avec ses raisons.

Des interdits absolus

Le travail non suivi par git, les fichiers suivis, les secrets (.env, .pem), le code source et les volumes Docker ne sont jamais proposés.

Rien ne part sans vous

Un aperçu, votre accord, puis la quarantaine : sept jours pour tout restaurer, avant la suppression définitive.

Votre stack

Reconnu à son manifeste, pas à son nom

Un dossier n’est proposé que si le fichier qui le reconstruit est à côté. Les règles en ombre reconnaissent déjà leurs dossiers et ne proposent rien tant que le corpus ne les a pas acceptées.

Le Brain

Un Brain qui apprend de vous, seulement vers la prudence

Le Brain de Delest pèse les règles, le contexte de vos projets et vos décisions passées. Le modèle local est une voix qu’il écoute sur les dossiers inconnus, jamais celle qui décide.

  • Il fonctionne sans modèleLes règles, les interdits, le contexte et la mémoire décident. Le modèle n’aide que sur les dossiers qu’aucune règle ne connaît.
  • Vos refus l’instruisentUn dossier refusé trois fois n’est plus proposé.
  • Une restauration est une leçonUn dossier remis depuis la quarantaine repasse « à juger » ; deux restaurations des dossiers d’une même règle mettent toute la règle en doute. Retenu 90 jours.
  • Il sait sur quoi vous travaillezLes dépendances d’un projet commité ces 30 derniers jours sont gardées : les réinstaller vous coûterait maintenant. Handoff, s’il est là, le lui dit aussi.
  • Apprendre ne lève jamais un interditLes habitudes ne rendent Delest que plus prudent : rien de ce qu’il apprend ne rend supprimable un dossier protégé.
  • Le modèle ne peut pas dire « supprimable »Ses réponses sont tenues par une grammaire : « à garder » ou « à juger ». Il ne tourne que si la mémoire et la batterie le permettent, et chaque avis est écrit dans un journal.
Vos agents

Une commande, et vos agents surveillent le disque

À chaque session, Delest regarde l’espace libre et ne dit rien, sauf quand le disque se remplit. Par MCP, vos agents peuvent aussi le lui demander.

Des hooks dans vos agents

Un contrôle au début de chaque session dans Claude Code, Codex, Cursor, Gemini CLI, VS Code (Copilot) et OpenCode ; dans Kiro par Vario. Dans l’application : Réglages › Contrôle à chaque session des agents, un bouton par agent. Dans un terminal : delest install, et delest remove les retire. Chaque fichier est sauvegardé.

Trois outils MCP, en lecture seule

delest_status (le disque et ce qui peut être libéré), delest_explain (les raisons pour un dossier), delest_scan (ce qui peut être libéré dans les dossiers donnés).

Demander à votre agent, sur un clic

Pour un dossier qui vous fait hésiter, l’application peut poser votre question à Claude Code : le chemin du dossier et les noms de ce qu’il contient, jamais les fichiers.

# les hooks, depuis un terminal
delest install

# Delest comme serveur MCP pour Claude Code
# Linux (.deb) ou Cargo
claude mcp add delest -- delest mcp
# macOS
claude mcp add delest -- /Applications/Delest.app/Contents/MacOS/delest mcp
# Windows (PowerShell)
claude mcp add delest -- "$env:LOCALAPPDATA\Delest\delest.exe" mcp

Avec l’application macOS ou Windows, delest reste dans l’application : donnez son chemin complet, comme ci-dessus, ou installez la commande avec Cargo.

Confidentialité

Votre code reste chez vous

Delest lit des noms de dossiers et des faits (taille, état git, manifestes voisins). Il n’ouvre pas vos fichiers pour les envoyer ailleurs.

  • Pas de compte, pas de publicité, pas de mesure d’audience.
  • Les modèles d’IA tournent sur votre machine, hors ligne.
  • « Demander à l’agent » n’envoie que le chemin du dossier et les noms de ce qu’il contient, et seulement sur votre clic.
  • Tout ce que Delest fait est écrit dans un journal, sur votre machine.

Questions

Questions fréquentes

Delest supprime-t-il quelque chose tout seul ?

Non. Il propose, vous choisissez, puis les dossiers vont en quarantaine pour sept jours. Rien n’est supprimé sans votre accord.

Et si j’ai besoin d’un dossier mis en quarantaine ?

Restaurez-le depuis la Quarantaine, ou avec delest restore, pendant sept jours. Au-delà, il est supprimé.

Faut-il un agent d’IA pour utiliser Delest ?

Non. L’application et la commande fonctionnent seules ; les agents ajoutent seulement un contrôle à chaque session.

Que fait Delest d’un dossier qu’il ne reconnaît pas ?

Il ne le propose pas. Le modèle local peut donner un avis, toujours vers la prudence, et la décision vous revient.

Delest télécharge-t-il des modèles d’IA tout seul ?

Non. Delest fonctionne sans eux. Dans Réglages › IA, « Installer l’IA locale » montre ce qu’il téléchargerait (environ 3,2 Go), et ne le fait qu’après votre accord ; chaque fichier est vérifié par son empreinte publiée. Le moteur demande macOS 13.3 ou plus récent, et sous Windows un runtime Visual C++ récent.

Combien coûte Delest ?

Rien. Delest est gratuit et open source, sous licence MIT : son code est sur GitHub.
